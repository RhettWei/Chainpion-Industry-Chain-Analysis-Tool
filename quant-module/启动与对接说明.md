# FutureChain 量化模块 v0.4.2 · 启动与对接说明

本包包含完整前后端源码，可独立运行，也可作为主 Agent 的计算服务。界面已精简；计算公式、审核防护和导出内容保留。示例财务与行情均为虚构／合成数据。

## 1. 先运行

运行环境：Node.js 20 或以上。核心功能没有第三方依赖，不需要 npm install，也不依赖 Codex。

1. 解压压缩包，进入 `quant-module` 文件夹。
2. Windows 双击 `启动量化模块.cmd`。也可以在该目录运行：
   ```powershell
   node server.mjs
   ```
3. 浏览器打开 `http://127.0.0.1:4318/`。终端窗口需保持运行。
4. 自检：在目录内运行 `node --test`。交付时 75 项测试通过。
5. 端口占用时，先设置 `$env:PORT = '4320'`，再启动；访问地址同步改成 4320。

服务只监听本机 127.0.0.1。不要双击 index.html，也不要用只提供静态文件的服务代替 server.mjs。

## 3. 推荐对接方式

### A. 主后端也是 Node.js：直接调用计算函数

```javascript
import { computeQuant, validateQuant } from './quant-module/src/models.mjs';

const validation = validateQuant(input);
if (!validation.valid) throw new Error(validation.errors.join('；'));
const result = computeQuant(input, { marketData, before: 5, after: 5 });
```

经营模型可省略 marketData / before / after；市场模型必须提供行情。validateQuant 的 valid 不表示所有必要财务都齐备：同时检查 missing；缺失对象会返回 status: "missing"，不能把缺失结果当零。

不要调用旧 computeOperating 代替统一入口，否则不能完整使用逐对象情景和四模型。

### B. 主后端不是 Node.js：内网 HTTP 调用

保留量化服务，由主后端向 `POST http://127.0.0.1:4318/api/compute` 提交 JSON。经营案例可直接提交 input，也可使用下面统一请求体：

```javascript
const response = await fetch('http://127.0.0.1:4318/api/compute', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ input, marketData, before: 5, after: 5 })
});
const result = await response.json();
if (!response.ok) throw new Error(result.error);
```

这是服务器间调用，不转发浏览器 Origin。浏览器不得跨域直连此开发服务：当前服务有同源 Origin 检查，没有 CORS、账号或鉴权。HTTPS 主站的浏览器请求应先到主后端，由主后端完成鉴权、来源校验和调用；不要直接反代带 HTTPS Origin 的请求，否则会被开发服务的检查拒绝。

### 前端适配注意

public 中使用绝对路径 `/api/...`、`/src/...`、`/styles.css` 等。不能直接搬到主站 `/quant/` 子目录就假定能运行。建议队友把页面组件合入主前端，统一调整资源、接口前缀及路由；或先将独立页面放在独立服务源中验证。尚未实现主站 iframe 通信桥或前端挂载接口。

## 4. 四模型与输入规则

| analysis.model | 必要输入 | 结果读取 |
|---|---|---|
| cost_transmission | 收入、毛利率、指定成本项占营业成本比例、变动成本比例 | result.companies：收入、毛利、桥接、情景、敏感性 |
| volume_price | 收入、毛利率、变动成本比例 | result.companies：量价、单位变动成本及利润影响 |
| break_even | 上述量价基准 + 固定经营费用 | result.companies[*].breakEven + 情景经营利润 |
| event_study | 事件日、截止日、证券和基准行情、交易日窗口 | result.marketStudy：证券 AR / CAR、组合收益、量 Z、回撤 |

推荐 schemaVersion 为 "1.0"，经营模型设置 `analysis.scenarioMode = "entity"`，每个 companies 元素必须有 scope 和 scenario。旧版全局参数仍兼容，但不应作为新研究的输入方式。

scope 指明 level（company / segment / product）、product、costItem、unit。只测一个产品时，各项基准也必须属于该产品，不能填公司合并收入。role 只是产业位置，不表示已经存在采购关系。

scenario 为每个对象独立设置：

```json
{
  "affected": true,
  "pricePct": 0,
  "volumePct": 0,
  "costPct": -10,
  "passThroughPct": 0,
  "lagMonths": 0,
  "fixedExpensePct": 0
}
```

- pricePct：scope.product 对应产品／业务的平均售价变化。
- costPct：成本模型作用于 scope.costItem 指定成本项；量价／本量利作用于该业务全部单位变动成本。切换口径时不能直接沿用。
- passThroughPct：成本上涨的转嫁／下降的让利；只用于成本模型。0 表示全部成本变化由本对象保留。
- lagMonths：只用于成本模型；horizonMonths 从 input.parameters 读取。不会自动年化基准收入。
- fixedExpensePct：额外固定经营费用变化，影响经营利润，不影响毛利。
- 未受影响对象 affected=false，所有变化参数必须为 0；量价／本量利的 passThroughPct、lagMonths 也必须为 0。
- 金额统一人民币万元；10 表示 10%，毛利率变化结果为百分点 pp。未知用 null 或省略，不能以 0 代替。成本比例的分母是营业成本，不是收入。
- 不自动推断需求弹性、不自动沿上下游传播；经营利润是简化口径，不是净利润预测。

事件文本的百分比仅是待审核草稿，不等于已核实事件或全公司冲击。主 Agent 应明确事件 → 对象 → 产品／成本项 → 参数，再调用测算。

### 行情输入

```json
{
  "companies": [{
    "id": "000001.SZ",
    "name": "样本名称",
    "prices": [{"date": "2026-09-01", "close": 10, "volume": 1000, "adjFactor": 1}]
  }],
  "benchmark": [{"date": "2026-09-01", "close": 3000}],
  "provenance": {"kind": "user", "provider": "数据来源", "volumeUnit": "手"}
}
```

以上只是格式片段，不足以计算收益；请使用 examples 中完整行情。日期为 YYYY-MM-DD，价格必须为正数。预期收益方法放在 input.analysis.marketMethod：market_adjusted 或 market_model（事件前 OLS）。OLS 至少需要 20 个有效估计日；不足时不可用，不自动降级。窗口按交易日，不是自然日；缺口保留，不补造零收益。

市场模型的顶层 companies / scenarios / sensitivity 为空。证券结果必须读 result.marketStudy.companies；完整目标日期在 result.marketStudy.window.dates，组合采用共同有效日期等权。CAR 的单位是 pp，不等于两条复利收益曲线之差，也不等于盈利变化或因果影响。

## 5. 来源、审核与任务状态

字段来源位于 companies[*].baselineSources，route 为 assumption / materials / online；资料与在线候选必须先被审核，再以 kind=reference、evidenceId 和 review 写入。evidenceId 引用 input.evidence 的非假设来源。review.status=approved，review.period 等于本次 context.periodLabel，reviewedAt 为合法 ISO 时间。

前端还记录 analysis.baselineReview 与 analysis.eventMapping。修改已确认的数值、来源、业务范围、日期或模型，应撤销确认并要求复核；情景滑块变化不改写基准。导入研究 JSON 会要求当前用户重新确认。

HTTP 或函数入口不会替调用者执行人工审核或鉴权。主 Agent 应维护任务 ID、用户权限、原文件、候选队列、确认记录和结果历史，不能把前端禁用按钮当成后端权限控制。

## 6. 后端接口

POST 请求使用 Content-Type: application/json；失败返回非 2xx + {"error":"说明"}。

| 路由 | 请求 / 返回要点 |
|---|---|
| GET /api/health | 服务状态、端口、凭证是否配置；不返回凭证 |
| POST /api/compute | input 或 {input,marketData,before,after} → 重算结果 |
| POST /api/material-extract | {name,text 或 base64,companyName,fields,asOf,periodLabel,publishedAt?} → candidates / warnings；不写入基准 |
| POST /api/baseline-references | {companyName,scope?,industry?,field,asOf,code?,periodEnd?,token?,searchKey?,primaryOnly?} → candidates / usage / warnings / manualLinks |
| POST /api/market-data | {eventDate,asOf,codes,benchmarkCode,token?} → companies / benchmark / provenance / usage / warnings |
| POST /api/export | {input,result,format,detail,charts?,delivery?}；市场模型另传 marketData / before / after |
| GET /api/download/<UUID> | 下载已生成文件；默认 5 分钟有效，服务重启后失效 |

导出服务的 format 只接受 docx / html / markdown，detail 为 brief / full。JSON / CSV 由前端本地生成，不是 /api/export 的格式。body.result 是兼容必需字段，但服务端仍从 input 和行情重算，不信任客户端盈利／市场数值。charts 为可选展示图，不承担数值校验。

delivery 不填时直接返回附件；delivery="link" 返回 {url,filename}，再请求 url 下载。开发服务最多保留 6 个临时报告；下载文件与行情缓存均为内存状态，不是永久资料库。

## 7. 数据接口与凭证

无需模型 API Key 即可进行确定性计算、参数探索和报告导出。外部数据获取需要另行配置：

```powershell
$env:TUSHARE_TOKEN = '填自己的 Token'
$env:BRAVE_SEARCH_API_KEY = '填自己的 Brave Search Key'
node server.mjs
```

按需设置，不必两项都有；也可在界面临时填写。服务不自动读取 .env 文件。临时凭证不保存、不导出；分享包中没有你的实际凭证，请通过你们认可的私密渠道另行配置。

- Tushare：daily / adj_factor / index_daily 用于行情；income 用于公司合并收入和毛利率候选。积分不能保证每个接口实际可用；权限及联网状态需在队友环境验证。
- Brave：已有正式搜索适配器，搜索 Key 与模型 Key 不是一回事；未配置时没有自动网页搜索。
- 成本结构与固定经营费用不能从普通利润表可靠“猜出”；找不到资料就保留缺失或明确使用情景假设。
- TXT / CSV / JSON / DOCX 解析为本地能力。PDF 解析器不随包附带：可选设置 PDFJS_MODULE 指向已安装 pdfjs-dist 的 legacy/build/pdf.mjs；缺少时改用可检索文字或其他格式。没有 OCR，也没有外发全文给模型。

## 8. 最小集成验收

包内 examples 都是合成数据，可直接作为 /api/compute 的请求体：

1. 成本传导输入_虚构.json：A 指定成本下降 10%，A 毛利增加 40 万元；B 未受影响，变化为 0。
2. 量价利润输入_虚构.json：A 平均售价提高 10%，销量／单位成本不变，A 毛利增加 100 万元；B 为 0。
3. 盈亏平衡输入_虚构.json：A 售价 −10%、销量 +15%、固定经营费用 +20%；经营利润 25 万元，盈亏平衡收入 960 万元，安全边际约 7.2464%；B 维持基线。
4. 事件研究请求_合成行情.json：预期收益采用事件前 OLS。结果仅位于 marketStudy，不能出现经营利润混用；逐证券 AR 加总应与其 CAR 一致。

请同时检查：修改参数只改变所选对象；缺失值不按 0；来源晚于截止日被阻止；报告中的模型、基准与页面一致；Word 能正常下载；主站的路径、鉴权和任务保存接通。

## 9. 尚未包含的生产系统能力

本包提供真实可运行的本机后端，不是纯静态页面；但不含账号、权限系统、任务数据库、持久化资料库、多人调度、邮件推送或生产部署。主 Agent 负责这些共用能力。不要把开发服务直接公开到公网。

原始资料及未审核候选只在本轮页面内存中；刷新后不恢复。已采用的来源、摘录与审核记录可随输入／报告导出。真实 Tushare / Brave 调用与权限没有在本次交付中验证；核心测试使用虚构财务、合成行情和模拟接口。
