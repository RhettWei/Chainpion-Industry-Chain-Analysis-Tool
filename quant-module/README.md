# FutureChain 独立量化模块 · 0.4.2

集成请先看 [启动与对接说明.md](启动与对接说明.md)。v0.4.2 精简界面教程、重复提示和字段解释，保留来源、单位、审核防护及可展开公式；核心公式和协议兼容 v0.4.1。当前操作名称以新版界面为准，本文历史更新章节保留方法说明。

本模块对应比赛的“产业链冲击对企业经营及盈利影响”量化环节。它可以单独启动、试用与导出，之后由一个数据适配层接入队友的产业链主模块。初版把可复算的经营情景、市场事件研究及数据证据放在同一页；演示企业和行情均显式标记为虚构。

## 启动与试用

需要 Node.js 20 或更新版本。使用标准库，不需要安装依赖。

```powershell
cd quant-module
node server.mjs
```

Windows 可以直接双击 `启动量化模块.cmd`，或运行 `./start.ps1`。启动器使用电脑上已安装的 Node.js。启动后打开 <http://127.0.0.1:4318/>，停止服务按 `Ctrl+C`。若 4318 被占用，可先设置 `$env:PORT = '4319'` 再启动。队友电脑需有 Node.js 20 或更新版本。

试用顺序：**直接选择模型 → 按字段选择获取方式 → 统一提取／查找候选 → 人工审核候选 → 查看整组基准与假设 → 确认并计算 → 拖动情景参数 → 导出报告**。不再勾选研究主题。进入页面不会自动计算演示财务。修改模型、基准、来源、研究日期会清除旧结果，须重新确认。滑块只调整情景，不改写已确认的基准。页面计算不需要模型 API Key，调整参数也不会调用外部接口。

## 四个模型与三路备数流程

v0.4 新增：基准准备先定义事件影响对象、公司／分部／产品范围及独立情景；无明确对象时不套用全局冲击。文末“v0.4 更新”说明新增协议和兼容边界。

| 模型 | 适用问题 | 必要基准 | 可调整参数 |
|---|---|---|---|
| 成本传导 `cost_transmission` | 指定采购成本如何作用于售价、毛利与经营利润 | 所选业务收入、毛利率、指定成本项占营业成本、变动成本占营业成本 | 每个对象独立：售价、销量、指定成本项单价、转嫁／让利、时滞、额外固定经营费用；共用期限 |
| 量价—利润 `volume_price` | 明确产品的销量、平均售价与单位变动成本同时变化 | 所选业务收入、毛利率、变动成本占营业成本 | 每个对象独立：产品均价、销量、单位变动成本、额外固定经营费用 |
| 本量利／盈亏平衡 `break_even` | 当前或新情景下的销量、收入门槛与安全边际 | 所选业务收入、毛利率、变动成本占营业成本、额外固定经营费用 | 每个对象独立：产品均价、销量、单位变动成本、额外固定经营费用 |
| 市场事件研究 `event_study` | 已发生事件的证券市场反应 | 证券与基准行情、复权、事件日、截止日及窗口；OLS另需事件窗口前至少20个共同日收益 | 预期收益方法、交易日窗口（修改后需重新确认） |

每张模型卡片可打开公式、符号、必填项、假设及限制。本量利模型把固定营业成本和额外固定经营费用合计一次；贡献毛益非正时不输出伪造的门槛。没有实际销量时，曲线横轴为基线销量倍数，不能解释为吨／台／件。

每张模型卡直接显示介绍、适配研究场景与输出。左侧以“量化模块”为主层级，下面依次是“选择模型、基准准备、审核与确认、结果与探索、资料与方法”；这些是模块内部步骤，不是五个同级 Agent 功能。市场模型的结果与探索自动切换到行情页面。

每个经营基准字段可以混用三条路线：

| 获取方式 | 用户操作 | 系统操作及边界 |
|---|---|---|
| 情景假设 | 直接填假设值，未知留空；需要时在资料记录中写依据 | 不联网，不冒充企业事实；核对整组后计算 |
| 从资料提取 | 上传／粘贴原文，按企业绑定一份资料或本轮全部资料 | 本机解析文字，按关键词与数值检索候选；保留摘录、单位、段落及企业匹配提示，不能自动解释复杂财务口径 |
| 联网补齐 | 一次配置临时凭证、财报期末与企业代码，点击统一查找 | 顺序查找全部待补字段，显示进度，可停止；财报与网页均先返回候选，不自动写基准 |

“审核与确认”分两层：先逐条候选核对企业、原文、期间／范围、单位、披露日和采用依据；再核对整组基准与当前情景假设。相同字段的冲突值并列，不求平均；采用一条后其他候选标为未采用。参考候选必须补齐披露日，不能晚于研究截止日。金额支持元、千元、万元、百万元、千万元、亿元转万元；比例0.22须明确选“比例（0～1）”，转换为22%。资料提取失败、单位未知或无可靠数值时保留缺口，允许补充原文或主动改成情景假设。

必要值空缺或参考路线未审核时不允许确认。可选固定经营费用空缺时只计算毛利；本量利模型中该费用必填。人工确认不等于系统独立核验真实性。改企业身份／研究期间／截止日等背景后参考值需重新查找审核；改联网代码或财报期末也使相关候选失效。修改模型要求重新确认；只调整滑块可实时复算。

## 本轮能做什么

| 能力 | 实际用途与边界 |
|---|---|
| 企业经营情景 | 从收入、毛利率、成本占比、固定经营费用和冲击参数，复算毛利及简化经营利润变化。不是完整净利润预测。 |
| 三情景及敏感性 | 比较不同假设下谁受益、谁受损、关键参数如何影响结果。情景不是概率预测。 |
| 图表与参数联动 | 参数变化后重算已输入数据；图表与结论同步更新。只有主动刷新行情才使用外部 API。 |
| 产业链角色比较 | 按用户指定的上游、中游、下游或其他角色比较独立情景。卡片不表示已核实的供应商客户边关系，也不自动计算企业之间的传导系数。 |
| 证据和缺口 | 保存来源、假设、字段缺失及计算方法。关键财务缺失时保留降级结论，缺失值不得变成 0。 |
| 市场事件研究 | 比较个股与基准的事件窗口收益、累计异常收益和成交量变化。结果是市场反应，不代表企业盈利变化，也不能证明因果。 |
| 资料导入与报告 | 输入 JSON 或企业基线 CSV；上传／粘贴原文提取候选；导出 Word `.docx`、Markdown 或 HTML，可选简版/详版。 |

内置演示里的“资源供应商 A”“电池材料商 B”“整车制造商 C”没有证券身份、真实公告或真实财报；合成行情也不是历史市场数据。报告必须保留这一标记。

原文资料支持粘贴文字、TXT、CSV、JSON、DOCX；本机有 PDF.js 时支持可检索 PDF。单件3MB、解析文字10万字符；扫描件不做OCR，旧.doc需转.docx。PDF解析器不是核心运行依赖：可配置 `PDFJS_MODULE` 指向本机 `pdfjs-dist/legacy/build/pdf.mjs`，本电脑亦可复用已安装的内置库；队友电脑缺少它时可粘贴文字或上传其他格式。没有外发文档、调用LLM或编造缺失数据。复杂表格、多期间和分部口径必须人工核验，资料提取仅是候选检索。

原文件及未审核队列只在本轮页面内存中，刷新不会恢复；采用后的摘录、来源、单位换算、披露日与审核记录进入输入和报告。未实现账号、任务数据库或资料永久存储；多人部署时由主Agent后端接管。临时Token/搜索Key不进入保存或导出。

## 输入协议与口径

版本化输入的正式字段见 [contracts/input.schema.json](contracts/input.schema.json)，完整示例见 [src/demo.mjs](src/demo.mjs) 的 `DEMO_INPUT`；`emptyInput` 提供空财务模板。

```json
{
  "schemaVersion": "1.0",
  "context": {
    "industry": "新能源汽车 · 动力电池",
    "eventDescription": "原材料价格上涨情景",
    "eventDate": "2026-09-01",
    "asOf": "2026-10-02",
    "periodLabel": "年度基线（万元）"
  },
  "parameters": {
    "shockPct": 10,
    "volumePct": 0,
    "passThroughPct": 40,
    "exposurePct": 100,
    "lagMonths": 1,
    "horizonMonths": 12
  },
  "companies": [{
    "id": "company-b",
    "name": "示例企业 B",
    "role": "midstream",
    "shockChannel": "cost",
    "baselineRevenue": 150000,
    "baselineGrossMarginPct": 22,
    "rawMaterialCostSharePct": 65,
    "variableCostSharePct": 85,
    "fixedOperatingCost": 14000,
    "evidenceIds": ["baseline-b"]
  }],
  "evidence": [{
    "id": "baseline-b",
    "kind": "user",
    "title": "用户录入年度基线",
    "source": "用户资料，需自行核验期间与口径",
    "description": "金额单位万元；比例单位百分比。"
  }]
}
```

主要字段约定：

- `eventDate` 是事件发生/公告日，`asOf` 是研究截止日，两者独立。未来事件可以做经营假设，但不能生成已发生的事件后市场反应。
- 初版金额统一为人民币万元，其他单位先换算再输入。`baselineRevenue` 和 `fixedOperatingCost` 使用同一期间；`periodLabel` 写明期间与单位。基线收入须大于 0；页面不会自动换算币种、财年或年化。分析期限只影响时滞后的冲击占比，不会把年度基线自动缩成季度基线。
- `baselineGrossMarginPct` 是收入的毛利率；`rawMaterialCostSharePct` 是基线营业成本中的原材料成本占比；`variableCostSharePct` 是营业成本中随销量变化的占比。原料视作变动成本的一部分，因此原料占比不可大于变动成本占比。百分比填写 `10` 表示 `10%`，不能填 `0.1` 表示 `10%`。
- `role` 取 `upstream`/`midstream`/`downstream`/`other`；`shockChannel` 取 `selling_price`（供给方售价冲击）或 `cost`（采购方成本冲击）。企业角色本身不决定计算公式，也不构成两家企业之间存在交易关系的证据。
- 金融数值未知时使用 `null` 或省略，不能填写 0 代替未知。0 可表示真实零值，因此两者含义不同。
- `evidence.kind` 取 `observed`（可核验观测）、`assumption`（假设）或 `user`（用户资料）。`evidenceIds` 引用输入中对应证据 ID；可附 `description`（说明）、`locator`（页码/表格/字段定位）、`publishedAt`、`url`、`page`。链接与发布日期未填写时应省略该字段，不填写空字符串。
- JSON Schema 不替代运行时的日期有效性、ID 重复、证据引用及财务口径检查。真实数据是否足以支持结论，仍取决于来源和假设，而不是文件能否解析。

企业 CSV 使用与 JSON 相同的英文字段。UTF-8 推荐列头如下，空单元格代表缺失：

```csv
id,name,role,shockChannel,baselineRevenue,baselineGrossMarginPct,rawMaterialCostSharePct,variableCostSharePct,fixedOperatingCost
company-b,用户企业 B,midstream,cost,150000,22,65,85,14000
company-c,用户企业 C,downstream,cost,300000,18,,75,35000
```

CSV 不包含完整情景和原始证据页码，导入后要补充研究问题、参数与证据描述；JSON 更适合与队友后端交换完整任务。

## 一个可手工复算的演示

内置“电池材料商 B”全部数值是假设。基线收入 150000 万元、毛利率 22%，因此营业成本为 `150000 × (1 − 22%) = 117000` 万元；原料占比 65%，受影响原料成本为 `117000 × 65% × 100% = 76050` 万元。原料涨幅 10%、时滞 1 个月、期限 12 个月时，有效冲击比例为 `11/12`，销量不变，所以原料成本增加 `76050 × 10% × 11/12 = 6971.25` 万元。假设其中 40% 通过提价转嫁，收入增加 `6971.25 × 40% = 2788.50` 万元；毛利变化为 `2788.50 − 6971.25 = −4182.75` 万元。

固定经营费用 14000 万元不变，则简化经营利润从 19000 万元降至 14817.25 万元。这里没有税费、利息、资本开支或产品组合变化，不能将其解释为真实净利润预测。销量变化、转嫁率或时滞一经修改，页面用同一公式复算。

“有利/不利”三情景会对每家企业按成本或售价渠道调整涨幅，并同时调整销量与转嫁率，用于压力测试；它们不是一个发生概率已知的统一宏观事件。上游售价渠道不使用成本转嫁率，也没有把同一原料涨价再次计为上游成本增加。

## 外部数据接口

初版真实行情接入 Tushare Pro 的 `daily`、`adj_factor`、`index_daily`，用于最多 5 家 A 股样本和一个指数基准。用户已有的积分不等于这些接口一定可用，实际权限在主动取数时验证。权限不足、网络失败或行情不足会显示具体错误；经营情景计算可继续使用已经输入的财务。

可以在页面数据设置临时填写 Token，也可以启动前在服务端配置：

```powershell
$env:TUSHARE_TOKEN = '填写你自己的 Token'
node server.mjs
```

Token 由服务端向 Tushare 发送，不写进代码、报告或输入文件。页面临时 Token 只用于当前请求，不保存到磁盘；服务端环境变量优先用于持续试用。模块没有自动读取 `.env` 文件，设置环境变量后需要重启服务。

### 基准参考查询

在基准准备页把待补字段选为“联网补齐”，展开“联网查找设置”，一次设置凭证、财报期末和每家企业代码，再点击“统一提取资料／查找待补数据”。**候选资料不自动覆盖输入**。用户须阅读来源、核对数值和期间、确认采用，才会记录为参考值。网页摘要不自动推断金额和成本比例；无Key的检索入口明确不是已搜得证据。批量任务可停止，已返回候选保留。

- 收入与毛利率：填写证券代码、季末日期、临时 Tushare Token（或服务端环境变量），查询 `income` 普通工商业累计合并财报。收入从接口金额元换算为万元；毛利率由 `revenue` 和 `oper_cost` 计算。缺失不是零，不拿营业总成本／净利率替代。过滤非合并、金融企业、非指定期末和截止日之后披露的资料。候选链接指向接口文档，**不是原始年报**，采用前仍需对照公告核验。最新财报接口不保证历史时点原始版本，不能仅凭披露日过滤就宣称完整点时回测。
- 通用资料：接入正式 [Brave Search API](https://api-dashboard.search.brave.com/documentation/services/web-search)，需要独立搜索 Key；不是 Paratera 模型 Key。可在查询窗口临时填写，或启动前设置 `$env:BRAVE_SEARCH_API_KEY = '自己的搜索 Key'`。默认筛选巨潮、交易所和政府来源；可关闭筛选查找其他研究资料。未配置搜索 Key 时不执行通用网页检索，页面明确标记外部检索入口并非已搜得资料。接口 Key 获取、额度与费用以服务商账户为准。
- 原料占比、变动成本占比和固定经营费用：不能由普通利润表可靠识别，本版不伪造参考数值，也不把销售／管理／研发费用全部当固定费用。找不到同口径资料时，应补充合同、管理资料或主动标注为研究假设，并用敏感性分析呈现不确定性。

[Tushare income 文档](https://tushare.pro/document/2?doc_id=33) 用于核对权限说明；实际是否能成功取决于账号权限、频率和网络。本轮使用模拟响应测试取数映射，未使用历史对话中的私密 Token，也未验证真实账号及 Brave 搜索 Key。临时 Token／Key 发起本轮查询时即清空输入框，仅在请求闭包使用，不保存、不导出。仅主动查询时调用外部接口。

主营业务构成、公告全文自动解析、深证信数据服务、SMM/Mysteel 现货、海关/UN Comtrade 等仍是后续接入候选，本轮未接入，也不假定免费或已授权。

## 与队友后端适配

先传递统一输入协议，再选具体连接方式。模块不需要连接队友数据库或复制登录系统；队友可在主任务中提供已核验数据及证据，将结果保存到自己的任务记录。

| 入口 | 调用与返回 |
|---|---|
| `GET /api/health` | 返回服务状态、Token／搜索 Key 是否已配置和端口，不返回密钥。 |
| `POST /api/compute` | 原始输入对象，按 `analysis.model` 返回确定性结果；兼容旧版缺少 `analysis` 的成本模型输入。事件研究传 `{input,marketData,before,after}`，返回 `marketStudy`。 |
| `POST /api/baseline-references` | `{companyName,industry?,field,asOf,code?,periodEnd?,token?,searchKey?,primaryOnly?}`；返回 `candidates/query/fetchedAt/usage/warnings/manualLinks`，只返回候选，不变更基准。 |
| `POST /api/material-extract` | `{name,text?或base64?,companyName,fields,asOf,periodLabel,publishedAt?}`；返回 `material/candidates/warnings/usage`。只在本机解析文字；原始数值单位保留，不变更基准。 |
| `POST /api/market-data` | 请求 `{eventDate,asOf,codes:["000001.SZ"],benchmarkCode:"000300.SH",token?}`；返回标准化 `companies`、`benchmark`、`provenance`、`usage`、`warnings`。 |
| `POST /api/export` | `{input,result,format,detail,charts?,delivery?}`；事件研究另传 `marketData,before,after`，服务端重算窗口，不信任传来的市场结论。保留所选模型、用户确认基准、字段来源、公式及局限。下载方式与 0.1 兼容。 |
| `GET /api/download/<UUID>` | 下载先前生成的报告，超时或服务重启后失效。页面保留可点击下载链接，避免自动下载被内嵌浏览器拦截。 |

市场标准化数据中，企业形如 `{id,name,role,prices:[{date,close,volume,adjFactor}]}`，基准为 `[{date,close}]`。日期使用 `YYYY-MM-DD`；Tushare `volume` 单位为手，出处写在 `provenance`。导入其他行情供应商时先适配此格式并保存原始单位及复权说明。

新版推荐直接导入 `src/models.mjs` 的 `computeQuant(input, {marketData,before,after})`、`validateQuant(input)` 和 `MODEL_CATALOG`。旧 `src/core.mjs` 保留原有成本公式与事件研究能力。协议仍为 `schemaVersion: "1.0"`，新增可选 `analysis` 和 `companies[*].baselineSources`：

```json
{
  "analysis": { "model": "volume_price" },
  "baselineSources": {
    "baselineRevenue": { "kind": "reference", "route": "materials", "evidenceId": "report-001", "review": { "status": "approved", "reviewedAt": "2026-10-02T12:00:00Z", "period": "年度基线（万元）" } },
    "variableCostSharePct": { "kind": "assumption", "route": "assumption", "evidenceId": "cost-estimate" }
  }
}
```

上例是字段片段：`analysis` 放输入顶层，`baselineSources` 放对应企业对象。`route` 为 `assumption/materials/online`。新参考路线必须提供有效非假设来源及approved审核记录；审核period等于当前基准期间，原文报告期另存locator。`analysis.baselineReview` 记录整组确认时间、期间、字段值及来源属性；改变已确认值、来源或期间时服务端拒绝陈旧确认记录，滑块变化不失效。旧无route协议继续兼容。事件研究独立输入可以省略财务parameters/companies/evidence/periodLabel；主模块传行情快照与事件窗口即可。UI导入会清除外部整组确认状态，要求本用户复核。程序调用旧接口不强制UI的人工确认流程；队友后端应按业务需要实施审批／权限，不能把前端禁用按钮当鉴权。

最终集成需确认：任务／企业 ID、统一货币和财年、来源链接、行情频率与复权、鉴权与保存位置。结构协议、计算方法版本和用户确认记录分别保留，避免旧研究不可复算。

服务默认监听本机 `127.0.0.1`，方便独立研发。若后续要发布给多人使用，由队友后端统一提供登录、鉴权、任务持久化与数据授权；本版本尚未提供这些能力。

## v0.4 更新（2026-10-08）

本版在 v0.3 基础上增加“事件 → 对象 → 参数 → 审核”闭环。新建研究不再继承统一 +10% 冲击；事件文字只产生待审核候选，不自动认定为事实或施加到全部公司。

- 明确公司／分部／产品范围、销售产品、成本项目和计价口径；各范围基准必须匹配。公司合并财报不作为产品收入。
- 经营模型使用 `analysis.scenarioMode="entity"`，每家公司提供 `scope` 和 `scenario`。售价、销量、单位成本、额外固定经营费用分别输入。成本模型另支持指定成本占比、转嫁／让利和时滞。未受影响对象所有变化归零。
- 三情景与敏感性逐对象计算；没有已确认采购关系时不自动把降本传播给其他企业。额外固定费用影响经营利润，不影响毛利。旧版 API 输入未声明 entity 时仍保留旧公式。
- 事件研究可选择 `analysis.marketMethod="market_adjusted"` 或 `"market_model"`。OLS只用事件窗口之前最多120个共同日收益，至少20日；样本不足或基准无波动时不回退、不造数、不声称因果。
- 新增对象影响正负条形图、基线／情景并排图、可点击与键盘操作的双参数毛利矩阵、证券CAR对比图。右侧参数仅调整所选对象。Word/HTML 导出保留对象范围与独立参数。
- 自动网页搜索采用 Brave Search API；在基准准备的“联网查找设置”填写临时Key，或在服务端设置 `BRAVE_SEARCH_API_KEY` 后重启。模型API Key和Tushare Token不能代替搜索Key。无Key保留手动原文检索入口，不伪称已联网。

核心仍是无新增依赖的 Node.js 本地服务；双击 `启动量化模块.cmd` 或运行 `node server.mjs`，打开 `http://127.0.0.1:4318/`。详见输入规范及 `test/entity-scenarios.test.mjs` 的可手算对接案例。
